# NDKTU Monitoring Platform

Camera-based attendance and monitoring platform.

- **Backend** — FastAPI + SQLAlchemy (async) + Alembic + APScheduler, Python 3.14, managed with [uv](https://docs.astral.sh/uv/).
- **Frontend** — React 19 + Vite + TypeScript + Tailwind CSS 4.
- **Database** — PostgreSQL 17 (runs in Docker).

---

## Prerequisites

- Docker & Docker Compose
- Python 3.14 + [uv](https://docs.astral.sh/uv/getting-started/installation/)
- Node.js 20+ and npm

---

## 1. Start PostgreSQL

From the repo root:

```bash
make up
```

This starts two containers via [docker-compose.yml](docker-compose.yml):

| Service | Host port | Credentials |
|---|---|---|
| `ndktu_db` (Postgres 17) | `5432` | `bekzod / qwerty`, db `camera_base` |
| `ndktu_pgadmin` | `5050` | `admin@admin.com / admin` |

Other Makefile targets: `make down`, `make ps`, `make revision`, `make upgrade`.

> **Heads up:** Postgres only honors `POSTGRES_USER` / `POSTGRES_PASSWORD` on **first** volume init. If you ever see `password authentication failed`, the volume was initialized previously with different credentials — reset it with `docker compose down && docker volume rm ndktu-monitoring-platform_postgres_data && make up` (destroys data).

## 2. Backend

```bash
cd backend
```

### 2.1 Create `.env`

Create [backend/.env](backend/.env) with the following content. The settings loader uses prefix `APP__` and `__` as nested delimiter (see [backend/app/core/config.py](backend/app/core/config.py)):

```env
# Database (matches docker-compose.yml)
APP__DATABASE__NAME=camera_base
APP__DATABASE__USER=bekzod
APP__DATABASE__PASSWORD=qwerty
APP__DATABASE__HOST=localhost
APP__DATABASE__PORT=5432
APP__DATABASE__ECHO=false
APP__DATABASE__ECHO_POOL=false
APP__DATABASE__POOL_SIZE=5
APP__DATABASE__MAX_OVERFLOW=10

# Application
APP__APP__HOST=0.0.0.0
APP__APP__PORT=8000
APP__APP__DEBUG=true
APP__APP__APP=main:app
```

### 2.2 Install dependencies

```bash
uv sync
```

### 2.3 Create the `uploads` directory

[backend/main.py](backend/main.py) mounts `/uploads` as static files; the directory must exist:

```bash
mkdir -p uploads
```

### 2.4 Apply migrations

```bash
uv run alembic -c app/alembic.ini upgrade head
```

(Or from the repo root: `make upgrade`.)

### 2.5 Run the API

```bash
uv run uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

- API: <http://localhost:8000>
- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>

## 3. Frontend

```bash
cd frontend
```

### 3.1 Configure the API URL (optional)

The frontend defaults to `http://localhost:8000` (see [frontend/src/pages/Employees.tsx](frontend/src/pages/Employees.tsx)). To point elsewhere, create `frontend/.env`:

```env
VITE_API_URL=http://localhost:8000
```

### 3.2 Install dependencies

```bash
npm install
```

### 3.3 Run the dev server

```bash
npm run dev
```

Open <http://localhost:5173>.

Other scripts: `npm run build`, `npm run preview`, `npm run lint`.

## 4. Database migrations

Create a new Alembic revision (autogenerated from model changes):

```bash
make revision
# prompts for a message
```

Apply pending migrations:

```bash
make upgrade
```

Migration files live in [backend/app/migrations/versions/](backend/app/migrations/versions/).

## 6. Troubleshooting

- **`password authentication failed for user "bekzod"`** — the Postgres volume was initialized with different credentials. See the Heads up note in section 1.
- **`Directory 'uploads' does not exist`** on backend startup — run `mkdir -p backend/uploads`.
- **`VIRTUAL_ENV=/usr does not match ...`** warning from `uv` — harmless; `uv` uses the project's `.venv` regardless.
- **CORS errors from the frontend** — the backend allows all origins by default (see [backend/main.py](backend/main.py)); make sure the backend is actually running on port 8000.
